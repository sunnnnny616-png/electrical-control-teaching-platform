# 平台框架改造：第一阶段实施记录 v0.1

日期：2026-08-22  
基线：`6b8f4b3 refine teaching shell and document cleanup handoff`

## 1. 本阶段结果

本阶段只改造 Platform Shell 与模块接入层，没有重建四个已完成电路。当前页面由显式 Registry 与 Module Loader 启动，第二章四个模块通过 Legacy Adapter 接入 Module Contract v1，同时保留原有 Geometry、ports、wires、deviceEdges、Solver、Current Flow 与电路渲染实现。

## 2. 新增平台层

- `src/schemas/module-contract.js`：Module Contract v1 校验与统一 Solver Result 空结构。
- `src/registry/module-registry.js`：显式注册、route/module alias 解析、章节查询和诊断。
- `src/platform/module-loader/module-loader.js`：模块切换、pause、unmount、scope dispose、mount、render。
- `src/platform/runtime/runtime-scope.js`：AbortSignal、timer/interval 与 cleanup 的模块级资源作用域。
- `src/platform/navigation/chapter-navigation.js`：章节导航与第二章模块列表。
- `src/platform/shell/platform-shell-v1.css`：目标平台五区布局与响应式覆盖。
- `src/chapters/chapter02/modules/legacy-module-adapter.js`：既有模块到 Contract v1 的适配器。
- `src/chapters/chapter02/modules/ch02_*/module.js`：四个模块的独立元数据定义。

## 3. Module Contract v1

模块运行实例必须提供：

- 状态与动作：`createInitialState`、`dispatchAction`、`reset`；
- 求解适配：`solve`、`normalizeSolverResult`；
- UI ViewModel：`getOperationViewModel`、`getStatusViewModel`、`buildTeachingFeedback`、`buildReplaySteps`；
- 生命周期：`mount`、`render`、`pause`、`resume`、`unmount`；
- 质量门：`validateGeometry`、`runTests`。

第一阶段 Adapter 直接调用当前 `index.html` 中已验证的实现。Contract 统一返回结构只是适配层，不改写原 Solver 的输入、规则或内部状态。

## 5. 生命周期与状态隔离

切换顺序固定为：旧模块 `pause` → `unmount` → Runtime Scope `dispose` → 新模块 `createInitialState` → 设置 active route → `mount` → `render`。

第一阶段切换时会停止回放、清除 pressed 外观并重置目标模块自己的 operation/solver state。现有全局监听器没有复制安装，因此不会随切换累积；后续新模块监听器应绑定到 Runtime Scope 的 `AbortSignal`。

## 7. 保护区核验

从 Git 基线提取并在当前 `index.html` 中逐字查验，以下片段均保持原样：

- topology / Geometry / ports / wires / deviceEdges；
- Solver / Current Flow / 各模块电路渲染；
- 原 `toggleQf1()` 动作逻辑。

新“QF 分闸”按钮仅在当前 QF 已闭合时调用原 `toggleQf1()`，不新增电气规则。

## 9. 回滚

第一阶段作为独立提交交付时，优先使用 `git revert <第一阶段提交>`，可同时恢复 `index.html` 并移除新增 `src` 平台层，不需要接触任何电路保护区。

如只回滚平台 UI，可单独恢复 `src/platform/shell/platform-shell-v1.css` 与对应 `index.html` 壳层结构；若保留 Registry/Loader，则不得移除脚本加载顺序或 `initializePlatformRuntime()` 启动入口。

下一阶段建议先把点动和正反转的状态/动作门面从内联脚本迁入各自模块目录，再迁移主电路与长动。仍以 Adapter 为过渡层，不复制或重写 Solver，不抽取 topology 数据，不主动公共化电路专用组件。
