# 平台框架改造：第二阶段门面迁移实施记录 v0.1

日期：2026-08-23  
基线：`e98da95 feat: introduce platform framework v1`  
实施提交：`5f8388d feat: migrate jog and reverse module facades`

## 1. 本阶段结果

点动与正反转已从 Legacy Adapter 迁移到 Facade Module Adapter。Platform 对这两个模块只使用 Module Contract 1.1 暴露的 StateSnapshot、Action、Solver Result、Operation ViewModel、Status ViewModel、Teaching Feedback 与生命周期接口，不再直接读取模块内部状态字段。

主电路与控制电路、长动控制在第二阶段仍保留 Legacy Adapter，作为第三阶段迁移对象。

## 2. 新增与调整的接入层

- `src/platform/module-adapter/facade-module-adapter.js`：标准 Facade 模块定义、生命周期转发与挂载状态管理。
- `src/chapters/chapter02/modules/ch02_jog/facade.js`：点动标准门面。
- `src/chapters/chapter02/modules/ch02_reverse/facade.js`：正反转标准门面。
- `src/schemas/module-contract.js`：Module Contract 升级到 1.1，并增加 Facade Schema 1.0、Action 与四类门面输出校验。
- `src/platform/module-loader/module-loader.js`：加载 Facade 模块时校验门面输出；加载失败时统一清理当前 scope。
- `index.html`：新增两个模块的私有 Port 和 Platform 通用门面渲染入口。

## 3. Module Contract 1.1

标准 Action 包含：

- `POWER_CLOSE`、`POWER_OPEN`
- `STOP_PRESS`
- `START_FORWARD_PRESS`、`START_REVERSE_PRESS`
- `JOG_PRESS`、`JOG_RELEASE`
- `PROTECTION_TOGGLE`、`PROTECTION_RESET`
- `RESET_MODULE`

Facade 模块必须返回：

- `StateSnapshot`：模块身份、操作状态、器件状态和电机状态。
- `SolverResult`：稳定器件状态、edge 状态、通电导线、保护状态、电机状态与扩展结果。
- `OperationViewModel`：电源、控制按钮槽位、保护动作与 Action State。
- `StatusViewModel`：右侧状态行、文案和值的视觉 tone。

## 4. Platform 与模块边界

调用链为：

```text
Platform Shell / DOM event
        ↓ 标准 Action
Module Loader → Facade Module Adapter
        ↓
Jog Facade / Reverse Facade
        ↓ 模块私有 Port
index.html 中现有动作函数与成熟 Solver
        ↓
标准 StateSnapshot / SolverResult / UI ViewModel
```

点动的 `state.jogControl.*` 和正反转的 `state.operationState.*` 只允许在模块私有 Port 中读取。Facade 完成公共结构转换；Platform 通用逻辑不判断这两个模块的内部字段。

## 5. 生命周期与状态隔离

Loader 固定执行旧模块 `pause`、`unmount`、scope dispose，再创建新 scope、执行 `createInitialState`、`mount`、门面校验与 `render`。加载中任一步失败都会执行 `disposeCurrent("module-load-error")`。

验证场景：点动合闸并按住运行，切换到正反转，再返回点动。返回后点动恢复为 QF 断开、SB 释放、KM 失电、电机停止；当前 scope 无遗留 timeout、interval 或 cleanup。
