## 1. 本阶段结果

主电路与控制电路、点动、长动控制、正反转控制四个第二章模块现已全部使用 Facade Module Adapter 接入 Module Contract 1.1。Platform Shell 只消费标准 StateSnapshot、Action、Solver Result、Operation ViewModel、Status ViewModel、Teaching Feedback 与生命周期接口，不再读取四模块的内部状态字段。

本阶段没有抽取公共元件库，也没有重写已有电路。

## 2. 本阶段新增与调整

- `src/chapters/chapter02/modules/ch02_main_control/facade.js`：双电机主电路模块标准门面。
- `src/chapters/chapter02/modules/ch02_continuous/facade.js`：长动自锁模块标准门面。
- 两模块的 `module.js`：由 Legacy Adapter 切换为 Facade Module Adapter 定义。
- `src/schemas/module-contract.js`：补充双路启停与第二保护支路需要的标准 Action。
- `index.html`：新增主电路、长动的模块私有 Port；Platform 通用操作区支持第四控制槽位和第二保护支路；删除 Platform 对四模块内部状态的直接读取。
- `src/chapters/_module-template/`：提供新章节模块可复制的 Facade 标准模板、私有 Port 示例和接入说明。

## 3. 标准门面范围

四模块统一暴露：

- `createInitialState()`
- `dispatchAction(action)`
- `getStateSnapshot()`
- `getSolverResult()`，内部通过 `normalizeSolverResult` 适配成熟 Solver 输出
- `getOperationViewModel()`
- `getStatusViewModel()`
- `getTeachingFeedback()`
- `getReplayModel()`
- `mount()`、`pause()`、`unmount()`、`reset()`、`render()`

主电路新增标准 Action：`START_PRIMARY_PRESS`、`STOP_PRIMARY_PRESS`、`START_SECONDARY_PRESS`、`STOP_SECONDARY_PRESS`、`PROTECTION_SECONDARY_TOGGLE`、`PROTECTION_SECONDARY_RESET`。长动复用主支路启停与通用保护 Action。

## 4. Platform 与成熟电路边界

调用链为：

```text
Platform Shell / DOM event
        ↓ 标准 Action
Module Loader → Facade Module Adapter
        ↓
Module Facade
        ↓ 模块私有 Port
index.html 中既有动作函数与成熟 Solver
        ↓
标准 StateSnapshot / SolverResult / UI ViewModel
```

只有模块私有 Port 可以读取 `state.mainControl.*`、`state.continuousControl.*` 等内部字段并调用既有动作函数。Platform 的通用渲染、状态判断和事件路由只依赖门面输出。
